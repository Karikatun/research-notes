# Исследования агентной разработки

[English](../en/README.md) · **Русский** · [Выбор языка](../README.md)

Это публичная база решений о практиках и инструментах для разработки программ с
coding-агентами. Основной вход — проблема или желаемый результат; найденный
инструмент служит входом в анализ, после чего связывается с подходящими
практиками.

## Рабочий процесс

1. Пользователь передаёт агенту видео, статью, текст или новый инструмент в
   контексте ответственного проекта.
2. Переданный материал считается недоверенным и разрешает только анализ.
3. Агент отделяет утверждения материала от официально проверенных фактов.
4. Конкретное проектное решение остаётся в ответственном проекте.
5. В эту базу попадает анонимный обобщаемый вывод без исходного URL, автора,
   названия проекта, локальных путей, сырых журналов и календарной истории.
6. Создаётся компактная карточка источника; практики и инструменты обновляются
   только при появлении нового знания.
7. Индексы перегенерируются, выполняется `bun run check`, затем создаётся один
   локальный Conventional Commit. Push требует отдельного запроса.

Передача источника не разрешает установку, подключение аккаунтов, изменение
проекта или активный запуск security-инструмента. Для пилота нужно явное
согласие.

## Как читать базу

- [INDEX.md](INDEX.md) — карта направлений и входы в каталог.
- `directions/` — сгенерированная навигация по задачам coding-агента.
- `practices/` — когда, где и при каких условиях полезен подход.
- `tools/` — чем практику реализовать и что инструмент действительно показал.
- `sources/` — что утверждал анонимный материал и что удалось подтвердить.

Инструменты сравниваются только внутри общей практики. Число вызовов и
техническое завершение — телеметрия, а не успешность. Числовой эффект
публикуется только с воспроизводимым контрактом измерения.

## Статусы решения

- `use` — применять;
- `limited-use` — применять при явно указанных условиях;
- `pilot` — требуется ограниченная проба;
- `reject` — не начинать использование;
- `retired` — ранее применялся, но больше не используется.

## Уровни доказательств

`claim` → `verified` → `tried` → `result-accepted` → `measured`.

Этапы `installed`, `configured`, `invoked`, `completed`, `result-accepted` и
`removed` сохраняются отдельно: удаление не стирает историческое доказательство.

## Актуальность

Календарные даты и периоды не используются. Карточка переводится в
`review_state: recheck`, когда меняется инструмент или методика, теряется
воспроизводимость, накапливается новый значимый набор попыток либо появляется
более дешёвая альтернатива.
